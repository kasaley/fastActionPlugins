# Плагины FastAction

Здесь живут плагины для [FastAction](https://github.com/kasaley/fastActionVersions) — и наши,
и присланные сообществом, — а также инструменты, которыми их собирают и выкладывают.

- **[Каталог](docs/catalog.md)** — что уже есть и что каждый плагин просит.
- **[Как написать плагин](docs/PLUGINS.md)** — API, песочница, описание экрана, примеры.
- **[plugins.json](plugins.json)** — тот самый список, который скачивает приложение.

Плагины не входят в приложение: пользователь ставит только то, что ему нужно, в
**Настройки → Плагины**.

## Быстрый старт

Нужен только Python 3 — зависимостей нет.

```sh
git clone https://github.com/kasaley/fastActionPlugins.git
cd fastActionPlugins

tools/fastplugin new weather --title Погода   # заготовка в plugins/weather.fastplugin
# …пишете plugin.js…
tools/fastplugin stamp weather                # обязательно после каждой правки скрипта
tools/fastplugin check weather                # манифест разобран и осмыслен
tools/fastplugin package weather              # build/weather.fastplugin.zip + sha256
```

Готовый плагин ставится через **Настройки → Плагины → Установить плагин…** — выберите
папку или собранный архив.

## Инструмент

| Команда | Что делает |
| --- | --- |
| `new <имя> [--title …]` | заготовка плагина: рабочий манифест и скелет `plugin.js` |
| `stamp [плагин…]` | считает sha256 скриптов и кладёт в `integrity` манифеста |
| `verify [плагин…]` | хеши на месте и совпадают со скриптами |
| `check [плагин…]` | манифест разбирается и осмыслен: права, хосты, настройки, `exec` |
| `package <плагин>` | собирает архив и печатает его sha256 |
| `entry <плагин> <url>` | печатает готовую запись для `plugins.json` |
| `index check` | проверяет `plugins.json` |
| `index audit` | скачивает каждый архив из индекса и сверяет хеш |
| `index page` | пересобирает `docs/catalog.md` из индекса |
| `release <плагин>` | тег, релиз GitHub и обновление записи в индексе |

## Как это проверяется

Подписи у плагинов нет. Доверие держится на двух хешах, и оба обязательны:

**sha256 каждого скрипта** лежит в `integrity` манифеста. Приложение сверяет его при
каждом запуске, поэтому плагин, отредактированный после установки, просто не запустится.
Отсюда правило: поправил скрипт — `stamp`.

**sha256 всего архива** лежит в записи каталога. Приложение считает его перед установкой,
поэтому подменить выложенный zip после ревью нельзя: пока запись не обновится через
pull request, приложение откажется ставить новый архив.

На каждый pull request к `plugins.json` CI скачивает архив, сверяет хеш с записью,
распаковывает и проверяет манифест внутри. Заявить в записи один хеш, а выложить другой
архив — единственный способ протащить чужой код мимо ревью, и это ровно та проверка,
которая его ловит.

## Чего это не даёт

Песочница ограничивает ущерб: у плагина нет файлов, нет сети помимо заявленных адресов,
нет способа запустить произвольную программу. Но плагину, которому пользователь сам дал
«сеть» и «секреты», ничто не мешает отправить свой токен на свой же сервер. Проверки
ловят подмену архива, а не злой умысел автора — поэтому ревью смотрит на код и на то,
объяснимо ли каждое запрошенное разрешение задачей плагина.

## Наши плагины

Jira и 1Password лежат в `plugins/` и выпускаются здесь же, своими релизами: у каждого
плагина свой цикл версий, и правка в плагине не ждёт выпуска приложения.

```sh
tools/fastplugin release jira     # тег jira-1.4.0, релиз, запись в индексе
```
