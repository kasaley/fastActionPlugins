# Каталог плагинов FastAction

[English](README.en.md)

Отсюда [FastAction](https://github.com/kasaley/fastActionVersions) берёт список плагинов.
Здесь же лежат руководство для авторов и инструмент, которым плагины собирают и выкладывают.

- **[Каталог](docs/catalog.md)** — что уже есть и что каждый плагин просит.
- **[Как написать плагин](docs/PLUGINS.md)** — API, песочница, описание экрана, примеры.
- **[plugins.json](plugins.json)** — тот самый список, который скачивает приложение.

Кода плагинов здесь нет: каждый живёт в своём репозитории и выпускается своими релизами.
Наши — [Jira](https://github.com/kasaley/FastActionJira) и
[1Password](https://github.com/kasaley/FastAction1Password) — по тем же правилам, что и чужие.

## Как попасть в каталог

1. Соберите плагин и выложите архив в релиз **своего** репозитория — ссылкой на конкретный
   тег, не на `latest`.
2. `tools/fastplugin entry <плагин> <ссылка на архив>` напечатает готовую запись.
3. Пришлите pull request с этой записью в `plugins.json`.

Проверки запускаются сами: архив скачивается, его хеш сверяется с записью, манифест внутри
разбирается и сверяется со своими хешами. Красный CI — значит запись и архив разошлись,
и ревью не начнётся, пока это не сойдётся.

## Инструмент

Нужен только Python 3 — зависимостей нет. Один и тот же файл работает и здесь, и в
репозитории одного плагина: он сам находит плагины в `plugins/` или в корне, а адрес
репозитория берёт у git.

```sh
tools/fastplugin new weather --title Погода   # заготовка плагина
tools/fastplugin stamp weather                # обязательно после каждой правки скрипта
tools/fastplugin check weather                # права, хосты, настройки, exec
tools/fastplugin package weather              # архив + sha256
tools/fastplugin entry weather <url>          # готовая запись для PR
tools/fastplugin index audit                  # скачать архивы из индекса и сверить хеши
tools/fastplugin index page                   # пересобрать оба каталога из индекса
tools/fastplugin release weather              # тег, релиз и запись для каталога
```

Скопируйте `tools/fastplugin` к себе в репозиторий плагина — он самодостаточен.

## Как это проверяется

Подписи у плагинов нет. Доверие держится на двух хешах, и оба обязательны:

**sha256 каждого скрипта** лежит в `integrity` манифеста. Приложение сверяет его при
каждом запуске, поэтому плагин, отредактированный после установки, просто не запустится.
Отсюда правило: поправил скрипт — `stamp`.

**sha256 всего архива** лежит в записи каталога. Приложение считает его перед установкой,
поэтому подменить выложенный zip после ревью нельзя: пока запись не обновится через
pull request, приложение откажется ставить новый архив.

Заявить в записи один хеш, а выложить другой архив — единственный способ протащить чужой
код мимо ревью, и `index audit` на CI — ровно та проверка, которая это ловит.

## Чего это не даёт

Песочница ограничивает ущерб: у плагина нет файлов, нет сети помимо заявленных адресов,
нет способа запустить произвольную программу. Но плагину, которому пользователь сам дал
«сеть» и «секреты», ничто не мешает отправить свой токен на свой же сервер. Проверки
ловят подмену архива, а не злой умысел автора — поэтому ревью смотрит на код и на то,
объяснимо ли каждое запрошенное разрешение задачей плагина.
